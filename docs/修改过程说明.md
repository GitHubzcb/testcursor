本次修改落实分析报告（`docs/主板测试程序问题分析与重构建议.md`）中的 **P0 止血清单全部条目**
及部分 P1 项。交付物分两类：

| 目录 | 内容 |
|------|------|
| `src/` | **完整修改版源文件**，可直接替换工程中的同名文件 |
| `patches/` | 两个超大文件（`MainBoardAfterAging.cpp` 9000+ 行、`OscilloscopeCommunication.cpp` 1200+ 行）的**定点替换指南**，每处修改附原代码/替换代码 |


`CSpreadSheet.cpp/.h`（Excel 方案更换属 P2 重构项）。

## 一、各文件修改过程

### 1. SerialPort.cpp / SerialPort.h（完整重写）

| # | 修改 | 解决的问题 |
|---|------|-----------|
| 1 | overlapped 读写事件改为类成员 `m_hReadEvent/m_hWriteEvent`，打开串口时创建、关闭时释放 | 原版每次读写 `CreateEvent` 从不关闭，**每小时泄漏约 13 万句柄**，跑久必死机 |
| 2 | 恢复 `GetOverlappedResult`（原版被注释）；超时走 `CancelIo` 后取结果 | IO pending 时返回 0，**数据被无声丢弃** |
| 3 | 修正 `ClearCommError` 判断逻辑（原 `!Clear... && dwErrorFlags>0` 写反） | 线路错误时不清理 / 清理时机错误 |
| 4 | 读、写各加 `CRITICAL_SECTION`；读写统一收敛到 `ReadCommInternal/WriteCommInternal` | **两个线程并发写串口造成发送帧交织**（传输异常首因之一） |
| 5 | `WriteFile` 的输入长度与输出长度分离（原版共用一个变量，pending 时返回值不可信） | 写入结果不可判断 |
| 6 | `CloseConnection`：先置断开标志 → `CancelIo` → 与读写互斥后再关句柄 | 关闭时仍有挂起 IO 的未定义行为 |
| 7 | 构造函数 `m_btParity/m_btStopBits` 初值互换修正 | 默认打开成 8E1 而非 8N1 |

对外接口不变：`ReadComm/WriteComm` 仍返回实际字节数，**0 = 失败/无数据**（全工程统一此语义）。

### 2. pc_m2_protocol.c / pc_m2_protocol.h（完整重写，协议布局不变）

| # | 修改 | 解决的问题 |
|---|------|-----------|
| 1 | `crc32_get` 实现真实 CRC32（poly 0xEDB88320，查表法），由新宏 `PC_M2_ENABLE_CRC32` 控制，**默认 0 = 兼容现有固件（填 0）** | 原版恒返回 0，线路误码完全无法发现；开关设计保证可与 MCU 固件分步同时启用 |
| 2 | 新增 `Pc_Com_Pack_Buf(flag, buf, len, out, out_size)`：组包到调用方缓冲、返回帧长、带容量校验（**线程安全**） | 原 `Pc_Com_Pack` 只能写全局 `dat/send_len`，被两个线程并发调用时**组包互相覆盖** |
| 3 | 原 `Pc_Com_Pack` 保留并转调 `Pc_Com_Pack_Buf`（兼容旧调用点） | 不破坏未改造的调用代码 |
| 4 | `bla_pc_test_elec_select_unpack`：`memcpy` 长度 `sizeof(pELModeStat)`（指针大小！）改为 `sizeof(tELModeStat)` | 结构体绝大部分内容没被拷贝 |

### 3. BLACommunicate.cpp / BLACommunicate.h（完整重写，公有接口全部保留）

| # | 修改 | 解决的问题 |
|---|------|-----------|
| 1 | 构造函数真正 `CreateEvent(m_ExitBlaThreadEvent)` | 原版从未创建就 Set/Reset/Wait（**野句柄**），关串口时轮询线程收不到退出信号 |
| 2 | 新增 `SendFrame()`：`Pc_Com_Pack_Buf` 组包到成员缓冲 + `m_csSend` 互斥 + 一次写出，所有命令统一走它 | **状态轮询线程与 UI 线程并发写串口 + 全局 dat 覆盖**（传输异常首因） |
| 3 | 返回值语义统一：`SendFrame` TRUE=整帧写出成功；修正 `PCSetBlaPageDisPlay` 等处"`length==0` 当成功"的反转判断，`curPage` 仅在发送成功后更新 | curPage 失步 → 页面门禁拒收新数据 → **界面停留旧值** |
| 4 | 接收线程改为**环形缓冲 + `TryExtractFrame` 逐帧提取**：帧前噪声丢弃、假帧头跳过重扫、任意分包/粘包、`len` 上限校验 | 原"校验 sticky_buf、解析 pBuf"错位 bug（分包帧被丢弃/解析成垃圾，115200bps 下 200+ 字节状态帧分包是常态）；`data_lenth` 无上限的越界读 |
| 5 | `pc_test_status` 更新加 `m_csStatus` 锁 + 时间戳 `m_dwLastStatusTick`；新增 `GetStatusSnapshot(dst, maxAgeMs)`/`IsStatusFresh()`/`GetMcuPageID()`；所有 `Get*` 改为"页面门禁→取快照→判 NaN"，**快照超过 1 秒即返回 FALSE** | 撕裂读（随机错误值）；**通讯中断后旧值继续参与判定**（症状③根因） |
| 6 | 页面门禁 `IsOnPage()`：`curPage` 或 MCU 状态帧回传的 `pageID` 命中其一即放行 | curPage 单点记账失步后 `Get*` 永久拒收 |
| 7 | `openBlaCOM`：防重复打开；先回收旧轮询线程再建新线程；复位状态数据。`closeBlaCOM`：SetEvent → **等待轮询线程真正退出（3s）** → 停接收线程 → 关串口 | 反复开关串口后**多个轮询线程并存**；对已关闭句柄读写 |
| 8 | `memset(data,0,sizeof(data))` 替代 `data[250]={0}` | 对下标 250 的**越界写** |
| 9 | `GetRFOutput` 成功路径补置 TRUE；`SetRFTestPageParameter` 修正 `sizeof(stim_param)`→`sizeof(setParam)`；各 `Set*` 返回真实发送结果（不再恒 TRUE）；`GetEleStimulationEleImpedanceValue` 加除零保护；`GetInformation` 强制字符串终止 | 一批吞错误/越界的小问题 |
| 10 | 接收线程顺带处理 `pc_com_device_info` 帧（解包到 `DeviceInfo` 并 `SetEvent(m_hDeviceInfoEvent)`） | 补全 0818 预留的设备信息通路 |

### 4. ElectrosurgicalAnalyzer.cpp / .h（完整重写）

| # | 修改 | 解决的问题 |
|---|------|-----------|
| 1 | **请求-应答序号匹配**：接收线程按行（\r/\n）组装完整应答 → 存 `m_strLastResponse` 并递增 `m_dwRespSeq`（临界区保护）；`getContIPV/getContPCf/getPULIPV` 发查询前记序号、等"本次"应答到达才解析，超时输出置 0 | 原版发查询后 `Sleep(100)` 就解析，而接收线程 300ms 才读一次——**拿到的几乎总是上一次的应答**（低/高档测试随机超差）；应答分包只取前半 |
| 2 | 新增 `getContIPVEx()` 带 BOOL 返回值（FALSE=本次查询无应答），旧接口转调保持兼容 | 上层可区分"读数无效"与"读数为 0" |
| 3 | 接收线程轮询 300ms→100ms | 降低应答延迟 |
| 4 | `closeElectrSurgAnalyzerCOM`：先停线程再关串口；`open` 防重复打开并复位应答缓存 | 对已关闭句柄读；重复起线程 |
| 5 | `interceptPULAllIP` 加除零保护 | fImA=0 时得到 inf |

## 二、集成步骤

1. **备份现工程**，将 `src/` 下 12 个文件覆盖到工程目录（同名替换）。
2. 按 `patches/OscilloscopeCommunication.cpp.修改指南.md` 替换 5 个函数、新增 2 个函数。
3. 按 `patches/MainBoardAfterAging.cpp.修改指南.md` 完成 12 处定点修改；
   其中修改 6 的"同类检查"务必执行（全文搜索 `UpdateData(`/`GetCurSel()`/`MessageBox(`
   在工作线程可达函数中的出现点）。
4. 编译说明：
   - 新文件带 **UTF-8 BOM**，MSVC 会自动按 UTF-8 解析并转换到工程执行字符集（GBK），
     中文字符串/注释在 MBCS 工程中行为不变，无需改工程设置；
   - `pc_m2_protocol.c` 若同时被 MCU 固件工程（IAR）编译，IAR 同样支持 BOM；
   - 新增了 `<vector>` 依赖（BLACommunicate），VS2015+ 无需额外配置。
5. **CRC 开关保持默认关闭**（`PC_M2_ENABLE_CRC32=0`），行为与现有固件兼容；
   待固件侧实现相同 CRC32 后，双方同时置 1 上线。

## 四、遗留事项（P1/P2，见分析报告第五、六节）

- 按钮处理函数中剩余的短 `Sleep`（200~600ms）建议后续统一移入工作线程；
- `OnTimer(2/3/4)` 的"按钮文字驱动状态机"建议 P2 阶段以表驱动测试引擎替换；
- CSpreadSheet（ODBC/Jet，仅 .xls）建议 P2 更换为 libxlsxwriter/OpenXML；
- CRC32 需与固件协商后同时启用；
- 建议为串口收发加原始字节日志（带时间戳落盘），作为后续问题定位与重构回归的基线。
